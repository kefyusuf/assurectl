# M4 Conformance Suite Design

**Status:** Draft for review  
**Date:** 2026-11-11  
**Milestone:** M4 — Signing, replay protection, issuer lifecycle (slice 3 of the milestone)  
**Base commit:** `d70d6801efc51ded7fb4b4c905c735f17ea3560c`  
**Scope:** a committed, downstream-implementer-facing conformance test suite covering all six schema drafts and the attestation signing/verification protocol — no production code changes

## 1. Purpose

Downstream implementers (self-hosters, app builders, protocol implementers) need a stable set of test vectors that pin the protocol's behavior: valid inputs that must succeed, invalid inputs that must fail closed, and deterministic outputs that must be reproduced byte-for-byte. The existing tests validate the Go implementation internally; the conformance suite makes those expectations consumable by any implementation in any language.

## 2. Deliverables

### 2.1 Conformance vector directory (`conformance/`)

A committed directory of JSON test vectors, one file per scenario, organized by protocol surface:

```
conformance/
  evidence-envelope/
    valid-minimal.json
    valid-full.json
    invalid-missing-subject.json
    invalid-bad-revision.json
    invalid-bad-digest.json
    invalid-stale-timestamp.json
    ...
  receipt/
    valid-advisory-approved.json
    valid-authoritative-rotation.json
    invalid-duplicate-requirement.json
    invalid-evidence-mismatch.json
    ...
  trusted-root/
    valid-initial.json
    valid-rotation.json
    valid-revocation.json
    invalid-rollback.json
    invalid-self-introduction.json
    invalid-expired-issuer.json
    ...
  check-payload/
    valid-success.json
    valid-failure.json
    valid-neutral.json
    ...
```

Each vector file is a self-contained JSON document with:
- `"description"`: what the vector tests;
- `"expect": "accept"` or `"expect": "reject"`;
- the protocol document itself under `"document"`;
- for signing vectors: `"signing_key_seed"` (base64) and `"expected_signature"` (base64) so implementations verify determinism.

### 2.2 Conformance harness (`internal/conformance/`)

A Go package that:
- reads every vector file in `conformance/`;
- for `accept` vectors: parses the document against the schema, runs the applicable validation, and asserts success;
- for `reject` vectors: asserts the validation fails;
- for signing vectors: verifies the signature against the trusted root and the expected signature;
- reports pass/fail per vector.

Downstream implementers can point their own runner at the same directory — the vectors are language-agnostic JSON.

### 2.3 Generation and maintenance

Vectors are generated by the existing test suite (`FIXTURE_UPDATE=1` pattern from `examples/signed/`). New vectors are added when a protocol edge case is found. The suite runs in CI alongside the existing tests.

## 3. Non-scope

- No production code changes to `internal/attestation`, `internal/evaluation`, `internal/receipt`, or other evaluator packages;
- no new schema drafts;
- no network, no Sigstore, no managed-scope infrastructure;
- no new dependencies.

## 4. Testing strategy

The conformance harness IS the test: each vector file is a test case. The suite passes when every vector's expectation matches the implementation's behavior. New vectors are added by adding files (and the implementation must handle them). The `FIXTURE_UPDATE=1` pattern regenerates signing vectors from the fixed seed.

## 5. Boundary

This slice completes M4's "conformance tests" item. Downstream implementers consume the `conformance/` directory directly; no Go-specific test framework is required to use the vectors.
